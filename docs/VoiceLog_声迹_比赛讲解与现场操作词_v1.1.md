# VoiceLog / 声迹 · 比赛讲解与现场操作词 v1.1

**用法。** 下面提供90秒介绍和约4分钟的产品浏览路线；时间是自选编排，不代表主办方限制。当前HTML使用明确标注的合成资料与模拟设备状态。正式比赛时可以替换为当天经过同意取得的录音；未替换的部分继续标注为样例。

## 1. 90秒产品介绍

> 大家好，我们做的是 VoiceLog / 声迹。今天我在讨论、采访、答疑和制作之间来回切换。录音豆把这些声音留下，VoiceLog 负责把这一天整理得能看、能查，也能继续使用。
>
> 打开后，上午的项目推进是一整块。展开里面，可以看到我们九点定的主线、十点做的访谈和十一点解决的问题。下午又是另一块，时间没有被打乱，也不用先看十几个零散录音。
>
> 切到人物交汇，纵向还是今天的时间。拖到下午，这个时段和我交流的人就靠近了。点开评审反馈，可以看到对方明确提出的关注点、几种有依据的理解，以及我可以怎样继续回应。每个解释都能回到原话，猜测也可以被否定。
>
> 这些内容会接成关联记忆。从一条反馈展开，可以看到原始交流、后来作出的修改和明天的安排。关系图可以自由拖动和缩放；点来源后还能回到刚才的位置。
>
> 最后，明确的日程经过确认进入安排。我们把声音接回自己已经在用的生活流程，让今天留下的内容明天还能用。

## 2. 约4分钟操作路线

| 时间 | 实际点击 | 可以直接说的话 | 画面应该出现 |
|---|---|---|---|
| 0:00—0:25 | 打开总览，指向Work设备条 | “采集端是这颗录音豆。这里用产品样例展示完整的一天，连接状态已标为示例。” | 实际产品图、快捷记录、日期、分块时间线 |
| 0:25—0:55 | 展开上午；再展开下午 | “上午这一段都在推进同一个项目，但其中有会议、访谈和答疑。外层看时段，里面看事情。” | 三项上午事情；下午六项事情，保持时间顺序 |
| 0:55—1:25 | 切人物交汇，拖到17:00，点评审反馈 | “时间还是这一天，只是换成人来读。当前交流的人靠近了，点击可以回到这一次交流。” | 头像轨道平滑换位、当前区间与详情 |
| 1:25—1:55 | 打开评审交流者，查看候选解释，点怎样回复 | “这段话明确要求能回到原话，所以‘希望核对依据’更有支持。‘已经决定给我们获奖’没有依据。回复是可编辑草稿，不会自动发给别人。” | 候选、原话、依据不足、可编辑回复 |
| 1:55—2:35 | 打开完整关系图；搜索“录音入口”；选节点并展开 | “一条反馈可以连接到一个改动，再连接到相关讨论。只强调我正在看的邻域，需要时再展开。” | 搜索结果、邻域强调、更多原话节点、可拖动画布 |
| 2:35—2:55 | 点蓝色引用；关闭来源页 | “这是它实际使用的文字和时间位置。返回后，刚才选中的节点和视角还在。” | 原话页、高亮、返回后位置保留 |
| 2:55—3:25 | 日历打开“参加颁奖环节”；核对后保存并导出 | “明确安排可以进入日历。当前存的是本机演示日历，导出的文件需要用户自己导入系统日历。” | 草稿→本机已存→ICS下载；不显示外部写入成功 |
| 3:25—4:00 | 返回总览，切多天或复盘 | “今天和谁谈了什么、哪些想法变了、明天需要接什么，都能从同一批记录继续看。夜间能力留作扩展预览，我们先把白天这条链做完整。” | 多天场景、复盘、未完成的安排 |

## 3. 两句有节目效果、但不混淆事实的话

**打开愿望便签时：**
> “我昨天随口说了句‘精妙绝伦，明天上台领奖’。它把这句留成了我的愿望；真正进日历的是主持信息里明确说过的‘参加颁奖环节’。热情可以有，事实不能替评委宣布。”

**看图谱里的反例时：**
> “它不仅留住我说得好的地方，也能让我看见哪个判断现在还站不住。”

## 4. 如果换成比赛当天真实录音

| 项目 | 替换条件 | 讲解口径 |
|---|---|---|
| 设备图与状态 | 官方SDK真实回执已经接上 | 根据真实状态说已连接／已取回，不沿用示例状态 |
| 录音与转写 | 本次录音获准，ASR实际运行且时间对齐 | 可说明实际采集、实际转写；保留低质量片段 |
| 人物身份 | 对方同意登记，或本人确认参与者 | 说“已确认参与者”；未经确认使用匿名标签 |
| 候选解释 | 确实运行对应模型 | 写明模型与运行状态；未运行仍标预置样例 |
| 原声定位 | 已绑定正确原文件且时长足够 | 当场播放；缺失时直接展示“原声未绑定” |
| 日历 | 获得真实服务回执 | 才说“已写入系统日历”；否则说本机保存／导出 |

## 5. 常见追问的回答

**手机也能录音，为什么要录音豆？**
“我们把采集位置和手机操作分开：讨论时手机还要看资料，录音豆可以独立收声和标记。我们会用相同App比较手机与录音豆的实际操作负担，不声称只有它才能录。”

**这是在判断别人心里怎么想吗？**
“展示的是针对当次表达的候选理解，有原话、有其他解释，也能被否定。它不生成别人的人格评分，不把猜测升格成事实。”

**Jev已经接了吗？**
“当前交互样例未连接模型。我们把候选生成、类型化判别和来源校验分开，Jev是后续判别接口的一种选择，仍要和中文模型做对照。”

**图谱为什么有用？**
“它让人从一次反馈找到相关讨论和后来修改，不必重新搜全部记录。图本身可与列表做消融，找回来源与理解变化的效率才是检验标准。”

**现在真做到了哪些？**
“分块、人物轨道、图谱交互、范围引用、修改、导入播放和本机日历都在浏览器里实际运行；设备、ASR、声纹、模型和外部日历还没有连接。交付报告逐项列出边界。”

## 6. 现场准备清单

- 下载单HTML或解压ZIP，提前在实际使用的浏览器完整点一遍；本机打开受限时使用包内本地启动脚本。
- 在“我的→原型说明”确认当前是演示资料；演示前可重置样例，避免上次操作残留。
- 把人物交汇时间先放在上午，现场拖到下午显示真实换位；减少动态效果系统偏好会关闭自动换位。
- 准备经过许可的短音频进行本机绑定；没有相符音频就保留缺失状态，不拿别的音频伪装原声。
- 确認投屏或录屏中字体和图谱节点可读；关系图有缩放、搜索和节点列表备选。
- 日历文件只含示例事件，不要导入常用日历；演示时优先使用测试日历。
- 讲解前填齐预赛信息卡和可访问链接，不用内部测试次数代替用户效果数字。
